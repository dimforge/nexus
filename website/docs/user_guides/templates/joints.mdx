Nexus accepts Rapier's [joint builders](https://rapier.rs/docs/user_guides/rust/joints/) for articulated mechanisms.
Refer to that guide for the joint types, local anchors, limits, and Degrees Of Freedom (DOF).
Nexus provides `state.insert_impulse_joint` in 2D and 3D, and `state.insert_multibody_joint` for its **3D**
reduced-coordinates solver. The difference between the two approaches is described in
[Rapier's joint constraints](https://rapier.rs/docs/user_guides/rust/joint_constraints/).

The `state.insert_multibody_joint` return value is `None` if the joint would create an invalid chain, e.g., a cycle.
Always check that insertion succeeded before using the returned handle. A [multibody](https://rapier.rs/docs/user_guides/rust/joint_constraints/#multibodies)
must have a tree structure. `state.insert_impulse_joint` can add a remaining loop-closing constraint, but that
constraint is still solved iteratively and can exhibit drift.

## Reading joint state

Call `state.read_multibody_links` to retrieve generalized coordinates, poses, and velocities.
<rust>The returned vector is ordered by environment, then by GPU traversal order.</rust>
<python>The returned NumPy arrays use the same order. See the
[readback example](./reading_and_modifying.mdx#reading-positions) for the array layout.</python>
Parent links precede their children. This isn't the integer order of
[`RigidBodyHandle`](https://rapier.rs/docs/user_guides/rust/rigid_bodies/#creation-and-insertion) values.
Link velocities are meaningful after the first `pipeline.simulate` call.

## Loading robots

The repository contains complete [URDF](https://github.com/dimforge/nexus/blob/main/crates/examples3d/rbd_urdf3.rs)
and [MJCF](https://github.com/dimforge/nexus/blob/main/crates/examples3d/rbd_mujoco_menagerie3.rs) examples.
<rust>The loaders populate the [`PhysicsWorld`](https://rapier.rs/docs/user_guides/rust/simulation_structures/)
returned by `state.rbd_world_mut(env)`. Register graphics with `viewer.insert_visual_shape`, then call `state.finalize`.
For continuous actuation, call `state.control_multibody_motors`; calling `state.rbd_world_mut` every frame would
mark the scene for rebuilding.</rust>
<python>`state.insert_urdf(path, options)` returns render shapes for `viewer.insert_visual_shape`.
The `state.insert_mjcf(viewer, scene_path)` method registers graphics itself. After `state.finalize`,
`state.apply_actuator_controls(viewer, ctrl)` applies a control vector in `state.actuator_names()` order. The
[Python examples](https://github.com/dimforge/nexus/tree/main/crates/nexus_python3d/examples) show the complete sequence.</python>

Keep `state.set_rbd_gravity` consistent with the robot model's up axis.
<python>For a Z-up scene, call `viewer.set_up_axis(Vec3.Z)` and set `state.set_rbd_gravity` to
`Vec3(0.0, 0.0, -9.81)` after `state.finalize`.</python> Changing the camera doesn't change gravity.
